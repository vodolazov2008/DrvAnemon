# Документация протокола ANEMON-AVTO

## Обзор

Протокол ANEMON-AVTO представляет собой JSON-основанный протокол связи поверх TCP для мониторинга и управления IoT-устройствами (датчиками температуры и влажности). Устройства отправляют данные о температуре, влажности и других параметрах на центральный сервер.

**Основные характеристики:**
- Транспорт: TCP
- Порт: 4004
- Формат данных: JSON
- Архитектура: запрос-ответ

## Структура сетевого взаимодействия

### Адресация
- **Клиент (устройство)**: 192.168.2.4 (динамические порты)
- **Сервер**: 178.250.240.73:4004 (статический адрес)

### Последовательность обмена данными

1. **Идентификация устройства** (Request Type 1)
2. **Синхронизация времени** (Time Sync Response)
3. **Отправка данных** (Request Type 2)
4. **Подтверждение получения** (Response Type 2)

## Типы сообщений

### 1. Request Type 1 - Идентификация устройства

**Направление**: Клиент → Сервер  
**Описание**: Простая идентификация устройства при подключении

**Структура JSON:**
```json
{
  "request": 1,
  "serial": "2023060019",
  "ip": "192.168.2.4"
}
```

**Поля:**
- `request` (int): Тип запроса = 1
- `serial` (string): Серийный номер устройства
- `ip` (string): IP адрес устройства

### 2. Time Sync - Синхронизация времени

**Направление**: Сервер → Клиент  
**Описание**: Синхронизация времени между сервером и устройством

**Структура JSON:**
```json
{
  "time": 1766818645,
  "last": 1766818586
}
```

**Поля:**
- `time` (int): Текущее время сервера (Unix timestamp)
- `last` (int): Время последнего получения данных (Unix timestamp)

### 3. Request Type 2 - Отправка данных устройства

**Направление**: Клиент → Сервер  
**Описание**: Подробные данные устройства с показаниями датчиков

**Структура JSON:**
```json
{
  "request": 2,
  "serial": "2023060019",
  "ip": "192.168.2.4",
  "device_name": "avto",
  "comment": "",
  "time_unix": 1766818645,
  "ssid": "MacBook",
  "pass": "Qweqwe123",
  "fw": "1.25",
  "arhive_type": 1,
  "temp_now": 24.2,
  "hum_now": 27,
  "temp_alarm": {
    "alarm_flag": 0,
    "high": 0,
    "low": 0
  },
  "hum_alarm": {
    "alarm_flag": 0,
    "high": 0,
    "low": 0
  },
  "alarm_delay": 0,
  "rssi": -63,
  "voltage": 4087,
  "measure_interval": 1,
  "sending_interval": 1,
  "sensor_type": "DTV01",
  "data": [
    {
      "ts": 1766818642,
      "t": 24.2,
      "h": 27
    }
  ],
  "data_size": 1,
  "last_rec": 4583
}
```

**Поля:**
- `request` (int): Тип запроса = 2
- `serial` (string): Серийный номер устройства
- `ip` (string): IP адрес устройства
- `device_name` (string): Имя устройства
- `comment` (string): Комментарий (может быть пустым)
- `time_unix` (int): Время отправки (Unix timestamp)
- `ssid` (string): SSID Wi-Fi сети
- `pass` (string): Пароль Wi-Fi сети
- `fw` (string): Версия прошивки устройства
- `arhive_type` (int): Тип архивирования
- `temp_now` (float): Текущая температура
- `hum_now` (int): Текущая влажность
- `temp_alarm` (object): Настройки температурных аварий
- `hum_alarm` (object): Настройки влажностных аварий
- `alarm_delay` (int): Задержка аварии (в минутах)
- `rssi` (int): Уровень сигнала Wi-Fi
- `voltage` (int): Напряжение питания (в милливольтах)
- `measure_interval` (int): Интервал измерений (в минутах)
- `sending_interval` (int): Интервал отправки данных (в минутах)
- `sensor_type` (string): Тип датчика
- `data` (array): Массив данных измерений
- `data_size` (int): Количество записей в массиве данных
- `last_rec` (int): Номер последней записи

**Особенности фрагментации:**
- Сообщения типа Request Type 2 могут быть фрагментированы на несколько TCP пакетов
- Первый пакет содержит JSON до массива `"data":[`
- Второй пакет содержит данные массива и завершение сообщения
- Сообщения заканчиваются символом `~` который не является частью JSON

### 4. Response Type 2 - Подтверждение

**Направление**: Сервер → Клиент  
**Описание**: Подтверждение успешного получения данных

**Структура JSON:**
```json
{
  "response": 2,
  "status": "ok"
}
```

**Поля:**
- `response` (int): Тип ответа = 2
- `status` (string): Статус операции ("ok" - успешно)

4. Отправляет Request Type 2 с данными
5. Получает Response Type 2 (подтверждение)
6. Закрывает соединение

## Особенности реализации

### Обработка фрагментации
При работе с протоколом необходимо учитывать, что сообщения Request Type 2 могут быть фрагментированы на уровне TCP. Рекомендуется:

1. Собирать все пакеты до получения полного JSON
2. Удалять завершающий символ `~` перед парсингом
3. Проверять корректность JSON перед обработкой

### Обработка ошибок
- При ошибках парсинга JSON сообщения игнорируются
- Неисправные TCP соединения закрываются и переустанавливаются
- Временная синхронизация обеспечивает корректную временную привязку данных

## Безопасность

### Потенциальные уязвимости
- Передача паролей Wi-Fi в открытом виде
- Отсутствие аутентификации на уровне протокола
- Незашифрованная передача данных

### Рекомендации по безопасности
- Использовать защищённые каналы связи (VPN, TLS)
- Избегать передачи чувствительных данных в открытом виде
- Реализовать аутентификацию устройств

## Заключение

Протокол ANEMON-AVTO представляет собой простую и эффективную систему для сбора данных с IoT-устройств. Основные преимущества:

- Простота реализации
- Низкие накладные расходы
- Поддержка фрагментации больших сообщений
- Автоматическая временная синхронизация

Основные недостатки:

- Отсутствие встроенных механизмов безопасности
- Потенциальные проблемы с фрагментацией для неопытных реализаций
- Отсутствие подтверждения доставки на уровне приложения
