# Реализация HTTP протокола версии 3 для DrvAnemon

## Обзор изменений

Драйвер DrvAnemon был полностью переработан для поддержки нового HTTP/JSON протокола версии 3, заменив собой устаревшие текстовые протоколы версий 1-2.

## Структура файлов

### Новые файлы
- `HttpServer.cs` - Встроенный HTTP сервер для приема POST запросов от устройств
- `ProtocolV3.cs` - Обработка JSON команд и формирование ответов
- `Test/AnemonHttpClient.cs` - Тестовый клиент для проверки протокола

### Обновленные файлы
- `Logic/DevAnemonLogic.cs` - Полная переработка логики устройства для HTTP протокола
- `Logic/DrvAnemonLogic.cs` - Обновление основной логики драйвера
- `DriverUtils.cs` - Добавление констант HTTP протокола
- `Logic/TagIndex.cs` - Обновление индексов тегов
- `DrvAnemon.Logic.csproj` - Включение новых файлов в компиляцию

### Удаленные файлы
- `Logic/Protocol.cs` - Старый протокол больше не поддерживается

## Архитектура HTTP протокола

### HTTP сервер
- **Порт**: По умолчанию 7120 (настраивается через конфигурацию)
- **Протокол**: Только POST запросы
- **Заголовки**: 
  - `Anemon-Protocol: 3`
  - `Anemon-Token: <токен_устройства>`
  - `Content-Type: application/x-www-form-urlencoded`

### JSON команды

#### Команда get_last_ts
```json
{
  "cmd": "get_last_ts",
  "data": [
    {
      "serial": "2023060019",
      "save_interval": 600
    }
  ]
}
```

#### Ответ get_last_ts_resp
```json
{
  "cmd": "get_last_ts_resp", 
  "ts": 1766418214,
  "data": [
    {
      "serial": "2023060019",
      "last_ts": 0
    }
  ]
}
```

## Конфигурация

### Параметры драйвера
- `HttpPort` - Порт HTTP сервера (по умолчанию 7120)
- `DeviceToken` - Токен для авторизации устройств (по умолчанию "3A:E7:4E:00:95:1E")
- `DataLifetime` - Время жизни данных в секундах (по умолчанию 600)

### Теги устройства
- `0` - Количество полученных пакетов
- `1` - Количество ошибок
- `2` - Время последнего обновления
- `3+` - Теги датчиков (индексация начинается с 3)

## Принцип работы

1. **Запуск**: При старте линии связи запускается HTTP сервер на указанном порту
2. **Прием запросов**: Устройства отправляют POST запросы с JSON командами
3. **Обработка**: Сервер валидирует заголовки, токен и обрабатывает команды
4. **Ответ**: Формируется JSON ответ и отправляется устройству
5. **Логирование**: Все операции логируются в систему мониторинга

## Безопасность

- Валидация токенов устройств
- Проверка версии протокола в заголовках
- Валидация формата JSON команд
- Обработка ошибок и исключений

## Тестирование

Для тестирования используйте класс `AnemonHttpClient`:

```csharp
var client = new AnemonHttpClient();
await client.SendGetLastTsCommandAsync("2023060019");
```

## Совместимость

- Полная замена старых протоколов версий 1-2
- Сохранение API для интеграции с RapidScada
- Поддержка до 256 датчиков на устройство

## Производительность

- Асинхронная обработка HTTP запросов
- Минимальные накладные расходы на парсинг JSON
- Эффективное управление памятью через словари данных

## Расширяемость

Архитектура позволяет легко добавлять новые команды:
1. Добавить обработку команды в `ProtocolV3.ProcessCommand()`
2. Реализовать логику в `DevAnemonLogic`
3. Обновить структуры данных при необходимости

## Логирование

Все операции протокола логируются:
- Запуск/остановка HTTP сервера
- Получение HTTP запросов
- Обработка команд
- Ошибки валидации и обработки
- Статистика устройств

## Миграция

При переходе со старых версий протокола:
1. Обновить конфигурацию устройств для использования HTTP протокола
2. Настроить порт и токен авторизации
3. Проверить совместимость команд
4. Обновить внешние системы интеграции
