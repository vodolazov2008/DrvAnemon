# Реализация TCP протокола ANEMON-AVTO для DrvAnemon

## Обзор изменений

Драйвер DrvAnemon был полностью переработан для поддержки протокола ANEMON-AVTO (TCP/JSON), заменив собой устаревший HTTP протокол версии 3. Новый драйвер обеспечивает совместимость с реальными устройствами ANEMON-AVTO согласно официальной документации протокола.

## Структура файлов

### Новые файлы
- `AnemonAvtoProtocol.cs` - Обработка TCP/JSON протокола ANEMON-AVTO
- `Test/AnemonAvtoTestClient.cs` - Тестовый клиент для симуляции устройств

### Удаленные файлы
- `HttpServer.cs` - HTTP сервер больше не используется
- `ProtocolV3.cs` - Старый HTTP протокол версии 3

### Обновленные файлы
- `Logic/DevAnemonLogic.cs` - Полная переработка для TCP протокола
- `DrvAnemon.Logic.csproj` - Обновление списка файлов

## Архитектура TCP протокола ANEMON-AVTO

### Основные характеристики
- **Транспорт**: TCP
- **Порт**: Берется из настроек линии связи Rapid SCADA (по умолчанию 4004)
- **Формат данных**: JSON
- **Архитектура**: запрос-ответ с инициацией от устройств
- **Фрагментация**: Поддержка фрагментированных TCP пакетов

### Типы сообщений протокола

#### 1. Request Type 1 - Идентификация устройства
```json
{
  "request": 1,
  "serial": "2023060019",
  "ip": "192.168.2.4"
}
```
**Ответ сервера**: Time Sync (синхронизация времени)

#### 2. Time Sync - Синхронизация времени
```json
{
  "time": 1766818645,
  "last": 1766818586
}
```
**Направление**: Сервер → Устройство

#### 3. Request Type 2 - Данные устройства
```json
{
  "request": 2,
  "serial": "2023060019",
  "ip": "192.168.2.4",
  "device_name": "avto",
  "comment": "",
  "time_unix": 1766818645,
  "ssid": "MacBook",
  "pass": "Qweqwe123",
  "fw": "1.25",
  "arhive_type": 1,
  "temp_now": 24.2,
  "hum_now": 27,
  "temp_alarm": {
    "alarm_flag": 0,
    "high": 0,
    "low": 0
  },
  "hum_alarm": {
    "alarm_flag": 0,
    "high": 0,
    "low": 0
  },
  "alarm_delay": 0,
  "rssi": -63,
  "voltage": 4087,
  "measure_interval": 1,
  "sending_interval": 1,
  "sensor_type": "DTV01",
  "data": [
    {
      "ts": 1766818642,
      "t": 24.2,
      "h": 27
    }
  ],
  "data_size": 1,
  "last_rec": 4583
}
```

#### 4. Response Type 2 - Подтверждение получения
```json
{
  "response": 2,
  "status": "ok"
}
```
**Направление**: Сервер → Устройство

## Конфигурация

### Параметры линии связи
- **Тип канала**: TCP-сервер
- **Порт**: Настраивается в свойствах линии связи (по умолчанию 4004)
- **Поведение**: Slave
- **Режим соединения**: Индивидуальное

### Пользовательские параметры линии связи
- `DataLifetime` - время актуальности текущих данных, с. По умолчанию 600.

### Параметры устройства
- **Строковый адрес** - идентификатор контроллера (серийный номер)

## Теги устройства

### Системные теги (индексы 0-2)
- `0` - Количество полученных пакетов
- `1` - Количество ошибок
- `2` - Время последнего обновления

### Датчики (индексы 100+)
- `100` - Текущая температура (°C)
- `101` - Текущая влажность (%)
- `200-455` - Исторические данные температуры (до 256 значений)
- `300-555` - Исторические данные влажности (до 256 значений)
- `400` - RSSI Wi-Fi сигнала (dBm)
- `401` - Напряжение питания (мВ)
- `500` - Версия прошивки (строка)

## Принцип работы

### Последовательность обмена данными
1. **Устройство подключается** к TCP серверу Rapid SCADA
2. **Отправка Request Type 1** - идентификация с серийным номером и IP
3. **Получение Time Sync** - синхронизация времени от сервера
4. **Отправка Request Type 2** - подробные данные с датчиками
5. **Получение Response Type 2** - подтверждение успешного получения
6. **Закрытие соединения** - устройство отключается

### Обработка фрагментации
- Сообщения Request Type 2 могут быть фрагментированы на несколько TCP пакетов
- Сообщения завершаются символом `~` (не является частью JSON)
- Драйвер автоматически собирает фрагментированные сообщения
- После получения завершающего символа происходит парсинг JSON

### Интеграция с Rapid SCADA
- TCP сервер Rapid SCADA автоматически управляет соединениями
- Драйвер обрабатывает данные через метод `ProcessTcpData()`
- Теги обновляются автоматически при получении новых данных
- Статистика и статус устройства отслеживаются в реальном времени

## Безопасность

### Текущие ограничения протокола
- Отсутствие аутентификации на уровне протокола
- Передача паролей Wi-Fi в открытом виде
- Незашифрованная передача данных

### Рекомендации
- Использовать VPN или защищенные каналы связи
- Настроить firewall для ограничения доступа к порту
- Регулярно обновлять прошивки устройств

## Тестирование

### Использование тестового клиента
```csharp
// Одиночный тест
await AnemonAvtoTestClient.RunSingleTestAsync("2023060019");

// Непрерывная работа
var client = new AnemonAvtoTestClient("2023060019");
await client.RunAsync();
```

### Запуск из командной строки
```bash
# Одиночный тест
dotnet run --project DrvAnemon.Logic -- --single 2023060019

# Непрерывная работа
dotnet run --project DrvAnemon.Logic -- 2023060019
```

### Проверка работы
1. Настройте линию связи в Rapid SCADA с TCP сервером на порту 4004
2. Запустите тестовый клиент
3. Проверьте поступление данных в Rapid SCADA
4. Убедитесь в корректности значений тегов

## Производительность

### Оптимизации
- Асинхронная обработка TCP соединений
- Эффективный парсинг JSON с использованием System.Text.Json
- Минимальные накладные расходы на обработку фрагментации
- Оптимизированное управление памятью через словари

### Масштабируемость
- Поддержка до 256 датчиков на устройство
- Обработка множественных TCP соединений одновременно
- Автоматическая очистка устаревших данных

## Логирование

Все операции протокола логируются:
- Установление TCP соединений
- Получение и обработка сообщений
- Парсинг JSON данных
- Ошибки обработки и валидации
- Статистика устройств

## Миграция с HTTP протокола

### Автоматические изменения
- Удаление HTTP сервера и связанных компонентов
- Замена HTTP обработчиков на TCP обработчики
- Обновление тегов для совместимости с новым протоколом

### Ручные изменения
1. Перенастройка линии связи с HTTP на TCP
2. Изменение порта с 7120 на 4004 (или настроенный порт)
3. Обновление внешних систем интеграции
4. Тестирование с реальными устройствами

## Поддержка и отладка

### Диагностические инструменты
- Подробное логирование всех операций протокола
- Статистика соединений и сообщений
- Мониторинг состояния устройств в реальном времени
- Тестовый клиент для проверки протокола

### Часто встречающиеся проблемы
1. **TCP соединение закрывается сразу** - проверьте настройки firewall
2. **Данные не поступают** - убедитесь в правильности серийного номера устройства
3. **Ошибки парсинга JSON** - проверьте корректность данных от устройства
4. **Фрагментация не работает** - убедитесь в наличии завершающего символа `~`
